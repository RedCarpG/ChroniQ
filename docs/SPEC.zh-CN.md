# ChroniQ 产品与技术规格

[中文](SPEC.zh-CN.md) · [English](SPEC.en.md) · [返回 README](../README.md)

本文描述当前实现及其验收要求，供开发、测试和功能维护使用。它不是待实现功能的路线图；涉及规则变更时，应同步更新英文版、对应源码和测试。操作细节见 [功能详解](features.md)，流派差异见 [流派说明](schools.md)。

## 1. 产品范围

ChroniQ 是面向手机和桌面浏览器的静态 Web 应用，将历法、天文可视化和多种命盘工具组合在一起。默认打开日历；页面包括日历、天象、观月、太阳系、八字、紫微斗数和西洋星盘。

- 不要求注册，不依赖应用后端、数据库或外部计算 API。
- 出生信息、命盘和偏好在浏览器本地使用，不提供云端同步。
- 可在线使用或安装为 PWA；离线能力取决于资源是否已缓存。
- 命理内容用于文化参考，不提供结果预测的科学有效性承诺。

## 2. 功能规格

| 编号 | 模块 | 当前范围 |
| --- | --- | --- |
| F-01 | 日历 | 月、周、年视图；公历与农历、节气、月相、干支及黄历详情；中国与法国假日选择；周起始日和显示项设置 |

## 3. 输入与时间契约

### 出生输入

以 [BaziInput](../src/lib/bazi.ts)、[输入验证](../src/lib/savedCharts.ts) 和 [地点验证](../src/lib/place.ts) 为准：

| 字段 | 含义及约束 |
| --- | --- |
| `year`, `month`, `day` | 公历出生日期；年份 1900–2100，日期必须真实存在 |
| `hour`, `minute` | 出生地钟表时间；小时 0–23，分钟 0–59，编辑中的空值不得提交给排盘 |
| `gender` | 当前排盘库的性别参数：`1` 为男、`0` 为女 |
| `place` | 可选地点：名称、纬度 −90…90、经度 −180…180、有效 IANA 时区；缺省地点为北京 |
| `trueSolar` | 可选真太阳时开关，作用于八字和紫微；西洋星盘使用对应 UTC 时刻 |

- 年、月变化时，日期控件将日期限制到该月的有效天数。
- 保存数据和分享链接都经过验证；坏数据不得直接进入排盘渲染。
- 夏令时跳变造成的不存在的出生时间不接受，表单提示改选时间；回拨造成的重复时间采用较早的一次，并显示说明。
- 底层 [时区转换](../src/lib/timeZone.ts) 对跳变区间采用向前移动的兼容策略，并返回 `gap` / `overlap` / `exact`；出生输入入口单独拒绝 `gap`。
- 真太阳时基于经度、当地历史时区偏移及均时差近似值计算。不同流派应通过现有设置表达，不应在组件中另写隐式规则。
- 行运精确相位先由每日采样确定区间，再求交会时刻，最后按出生地时区落到日历日期，覆盖当地年的边界。

## 4. 本地数据与分享

- 命盘、最后一次出生输入、合盘对象及界面偏好存入 `localStorage`；当前选中对象、菜单、缩放等交互状态按各页面生命周期管理，不保证重新打开后恢复所有交互状态。
- 存储不可用时保留可用的会话状态；读取损坏条目时验证并回退到合法默认值或忽略无效条目。
- 没有服务端备份或跨设备同步。浏览器站点数据被删除后，本地命盘不能由服务器恢复。
- 分享协议使用 URL `#` 片段，见 [shareLink.ts](../src/lib/shareLink.ts)：

| 参数 | 内容 |
| --- | --- |
| `t` | `bazi`、`ziwei` 或 `star` |
| `d` | `YYYY-MM-DDTHH:mm`，出生地本地时间 |
| `g` | `m` 或 `f` |
| `pn`, `lat`, `lon`, `tz` | 可选地点名称、经纬度和时区；分享时经纬度取小数点后两位 |
| `ts` | `1` 表示真太阳时 |
| `lng` | 兼容旧链接的经度参数 |

片段不会随普通 HTTP 页面请求发送给站点服务器，但接收者可以读取其数据。链接不包含已保存命盘列表、流派选项或界面偏好，接收端按其设置计算。打开时解析一次并移除地址栏中的片段；日期等核心字段无效时不载入该分享，地点无效时可回退到默认地点。

## 5. 视觉与交互规格

- 日期、农历、干支是日历详情的主信息；该卡使用统一的思源宋体，说明与宜忌使用 400 字重、13px 及较低对比度。主题变化后仍须保持可读性。
- 天象表格的「宿」列使用 400 字重，保留低饱和度的四象色调，不用颜色和粗体抢占天体信息的重点。
- 选中星体时保留选中轨迹；悬停其他星体可以同时显示其轨迹，但不取消已有选择。
- 选中天体的日轨迹及历史轨迹以 3.2 秒周期在透明度 0.8–1 之间缓慢变化。悬停轨迹不呼吸；流畅模式、拖动时间及 `prefers-reduced-motion: reduce` 下禁用此效果。
- 页面应适配窄屏；键盘可操作核心控件，表单和图形控件提供可访问名称。浏览器定位由用户主动触发并授权。
- 英文界面翻译操作文字；干支、神煞、紫微星曜等专有名词仍保留中文并遵循繁简设置，部分术语解释仍为中文。

## 6. 技术结构

| 层次 | 入口与职责 |
| --- | --- |
| 应用壳 | [App.tsx](../src/App.tsx)：页面切换、共享出生输入和设置 |
| 页面与组件 | [components/](../src/components/)：日历、排盘、天文页面及通用交互 |
| 计算 | [lib/](../src/lib/)：历法、排盘、时区、地点、天文模型和校验 |
| 后台计算 | [chartWestern.worker.ts](../src/lib/chartWestern.worker.ts) + [westernClient.ts](../src/lib/westernClient.ts)：年度行运请求、取消、结果与错误处理 |
| 星空绘制 | [skyGeometry.ts](../src/components/skyGeometry.ts)、[skyScene.ts](../src/components/skyScene.ts)、[useSkyBackdrop.ts](../src/components/useSkyBackdrop.ts)、[skyPaint.ts](../src/components/skyPaint.ts)：几何、场景、独立图层缓存与画布绘制 |
| 翻译 | [i18n/](../src/i18n/)：中文原文键、英文词典、占位符与覆盖检查 |
| PWA | [scripts/pwa.ts](../scripts/pwa.ts) + [sw-template.js](../scripts/sw-template.js)：生产资源清单和 Service Worker |

运行栈为 React 19、TypeScript、Vite；历法与八字依赖 tyme4ts，紫微依赖 iztro，天文计算依赖 astronomy-engine。`legacy/` 不属于当前应用构建路径。

## 7. 性能与离线约束

- 日历为默认首屏，八字等非首屏界面按需加载；太阳系不能仅为引用颜色表而加载整个天象界面。
- 年度行运计算在 Worker 中执行。离开日历或更换相关条件时取消不再需要的任务；失败后提供重试，取消不能被当作计算失败。
- 缓存有容量上限：年度行运客户端 24 条、日历年度 48 条、八字命盘 16 条；容量不是对所有页面的性能时限承诺。
- 暗星、星云及深空星场分别缓存坐标；只改变一个图层的细节条件时，不应重算未受影响图层。
- 生产 Service Worker 预缓存最终构建文件，HTML 内容和脚本变化都影响版本号；被 Vite 删除的中间文件不能进入清单。
- 新 Worker 等旧版受控页面关闭后激活；页面使用与活动 Worker 配套的 HTML，避免新旧模块混用。
- 字体切片和高分辨率月球贴图等资源按需缓存，离线时允许降级。首次访问且尚未缓存时不保证离线可用。
- 开发服务器不注册 Service Worker；不能用开发服务器的成功启动代替离线验证。

## 8. 验收标准

下表编号与英文版一致。它定义回归检查，不表示每项都已完全自动化。

| 编号 | 场景与预期 |
| --- | --- |
| A-01 | `npm ci` 后测试和生产构建成功，类型检查通过；PR 流程执行相同核心检查 |
| A-02 | `2026-02-31`、平年 2 月 29 日及空出生时间不能使排盘崩溃；合法闰日和午夜可以提交 |
| A-03 | 纽约 `2024-03-10 02:30` 不可作为出生时间提交；`2024-11-03 01:30` 采用较早时刻并提示 |
| A-04 | 合法分享可直达对应排盘页；无效日期和损坏的合盘缓存不会触发渲染异常 |
| A-05 | 行运日期按出生地时区确定，测试覆盖跨日；后台计算可取消、可重试且复用有界缓存 |
| A-06 | 日历首屏依赖中没有八字界面；太阳系静态依赖链中没有 `SkyView`；所有预缓存路径均存在于最终产物或公共资源中 |
| A-07 | 旧页面在新版等待时仍可加载旧模块；关闭旧页面后新版可激活，删除旧缓存且保留其他应用缓存 |
| A-08 | 完成首次缓存后，生产页面可离线重载并运行已缓存的核心功能；可选资源按约定降级 |
| A-09 | 深浅主题、窄屏下文字层级清晰；「宿」列保持常规字重；轨迹呼吸只作用于选择且遵循减少动态效果设置 |
| A-10 | 星空缩放、拖动、画质、视角、星座切换和选择保留正确行为；无关图层不因细节阈值变化重复转换坐标 |

自动测试使用 Vitest；组件测试使用 happy-dom，不能替代真实布局、画布、字体或 Service Worker 验证。涉及这些路径时，应补充真实浏览器检查。运行命令、翻译与生成脚本见 [开发指南](development.md)。

## 9. 构建与发布

推荐 Node.js 22，与 [CI](../.github/workflows/pages.yml) 一致。依次使用 `npm ci`、`npm test`、`npm run build`；`npm run typecheck` 可独立执行类型检查。`npm run preview` 预览 `dist/`。

`dist/` 可作为静态站点部署；Vite 使用相对资源路径。GitHub Actions 在 PR 上测试和构建，在 `main` 上额外部署到 GitHub Pages。本地成功构建不等于已发布。
